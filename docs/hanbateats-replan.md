# 한밭이츠 재기획 초안

## 1. 한 줄 결론

한밭이츠는 한밭대학교 주변 학생들이 배달비와 최소 주문 금액 부담을 줄이기 위해, 핸드폰 번호로 간단히 로그인하고 근처 공동 주문 방에 참여하는 모바일 중심 배달 매칭 서비스다.

## 2. 전체 그림

사용자는 앱을 켜고 핸드폰 번호로 로그인한다. 로그인 후에는 현재 모집 중인 배달 공동 주문 방을 확인한다. 마음에 드는 방에 들어가 메뉴와 가격을 입력하면, 방의 총 주문 금액이 실시간으로 올라간다. 최소 주문 금액을 넘으면 방장이 모집을 마감하고 실제 주문을 진행한다. 주문 후에는 영수증 사진이나 주문 내역을 기준으로 정산한다.

처음부터 결제, OCR, 자동 송금까지 모두 만들면 범위가 너무 커진다. 그래서 1차 목표는 공동 주문 흐름을 확실하게 만드는 것이다. 이후에 OCR 정산, 에스크로, 알림, AWS 배포 같은 기능을 단계적으로 붙인다.

## 3. 왜 필요한지

한밭대학교 기숙사나 덕명동 원룸촌에 사는 학생은 혼자 배달을 시킬 때 세 가지 문제를 자주 겪는다.

- 배달비가 비싸다.
- 최소 주문 금액을 채우기 어렵다.
- 모르는 사람과 돈을 주고받기 불안하다.

한밭이츠는 이 문제를 앱 안의 방, 주문 금액 합산, 상태 관리, 정산 기록으로 해결한다. 실무 관점에서는 단순 게시판보다 더 좋은 주제다. 이유는 사용자 인증, 방 상태 관리, 실시간 통신, 데이터베이스 설계, 알림, 정산 로직처럼 백엔드에서 중요한 개념을 자연스럽게 다룰 수 있기 때문이다.

## 4. 쉬운 비유

한밭이츠는 카카오톡 단체방에서 “치킨 같이 시킬 사람”을 찾는 일을 앱이 대신 정리해주는 서비스다.

카카오톡에서는 누가 참여했는지, 얼마가 모였는지, 모집이 끝났는지, 누가 돈을 냈는지 직접 확인해야 한다. 한밭이츠에서는 서버가 이 장부를 들고 있다. 사용자는 메뉴를 입력하고 상태만 확인하면 된다.

## 5. 핵심 사용자 흐름

### 5.1 로그인

- 핸드폰 번호만 입력한다.
- 실제 서비스에서는 문자 인증 코드를 추가한다.
- 캡스톤 1차 구현에서는 개발 속도를 위해 인증 코드는 임시로 처리할 수 있다.

### 5.2 홈 화면

- 현재 모집 중인 방을 보여준다.
- 방마다 가게명, 배달 플랫폼, 최소 주문 금액, 현재 모인 금액, 모집 상태를 보여준다.
- 마감된 방은 색과 상태 표시를 다르게 보여준다.

### 5.3 방 생성

- 플랫폼을 선택한다.
- 가게명을 입력한다.
- 최소 주문 금액을 입력한다.
- 픽업 위치를 입력한다.
- 모집 마감 시간을 입력한다.

### 5.4 방 참여

- 참여자는 메뉴명과 가격을 입력한다.
- 서버는 현재 총액을 다시 계산한다.
- 방에 들어와 있는 사람들에게 실시간으로 변경된 금액을 전달한다.

### 5.5 모집 마감

- 최소 주문 금액을 넘으면 방장이 모집을 마감할 수 있다.
- 참여자가 빠져서 금액이 다시 부족해지면 모집을 다시 열 수 있다.
- 완전 주문 완료 상태와 단순 모집 마감 상태는 분리한다.

### 5.6 정산

- 1차 구현: 방장이 영수증 금액을 직접 입력하고 참여자별 금액을 확인한다.
- 2차 구현: 영수증 이미지를 OCR로 읽어 메뉴별 금액을 자동 검증한다.
- 3차 구현: 에스크로 또는 간편 송금 연동 가능성을 검토한다.

## 7. 추천 기술 구조

### 프론트엔드

- 초기 프로토타입: HTML, CSS, JavaScript
- 실제 앱형 개발: React 또는 React Native
- 모바일 제출용: PWA 또는 React Native 중 선택

### 백엔드

- Spring Boot
- PostgreSQL
- Spring Security 또는 JWT
- WebSocket
- AWS EC2 또는 Elastic Beanstalk
- S3 for 영수증 이미지 저장

### 이유

Spring Boot는 백엔드 캡스톤에서 설명하기 좋고, PostgreSQL은 관계형 데이터 모델을 명확하게 보여주기 좋다. WebSocket은 방의 현재 주문 금액을 실시간으로 보여주는 핵심 기능에 필요하다.

## 9. 상태 설계 초안

방 상태는 단순히 열림/닫힘으로 보면 나중에 꼬인다. 최소한 아래처럼 나누는 것이 좋다.

- OPEN: 모집 중
- PAUSED: 최소 금액 달성 후 방장이 모집 마감
- ORDERED: 실제 주문 완료
- SETTLING: 정산 중
- DONE: 정산 완료
- CANCELED: 방 취소

## 10. 디자인 방향

참고 이미지의 색상은 브랜드 포인트로 사용한다.

- red: 시작, 알림, 주요 강조
- warm: 따뜻함, 음식, 브랜드 배경
- teal: 신뢰, 상태 표시
- navy: 정보, 텍스트, 금액

로그인 화면에는 이 네 가지 색으로 만든 귀여운 블록형 로고를 크게 보여준다. 그 뒤의 앱 화면은 너무 장난스럽기보다 학생들이 반복해서 쓰기 편한 깔끔한 모바일 앱 느낌으로 잡는다.

## 12. 자주 헷갈리는 부분

### 핸드폰 번호 로그인과 문자 인증은 다르다

핸드폰 번호만 입력해서 로그인하는 것은 개발용 간편 로그인이다. 실제 서비스처럼 안전하게 하려면 문자 인증이 필요하다.

### 모집 마감과 주문 완료는 다르다

모집 마감은 더 이상 사람을 받지 않는 상태다. 주문 완료는 방장이 실제 배달앱에서 주문을 끝낸 상태다. 이 둘을 같은 상태로 만들면 정산 흐름이 꼬일 수 있다.

### OCR은 핵심 기능이지만 첫 구현 대상은 아니다

OCR은 멋진 기능이지만 처음부터 넣으면 프로젝트가 무거워진다. 먼저 사람이 직접 입력하는 정산 흐름을 만들고, 그다음 OCR을 붙이는 편이 안전하다.

## 13. 내가 직접 말로 설명할 수 있는 핵심 정리

한밭이츠는 한밭대 학생들이 배달비와 최소 주문 금액 부담을 줄이기 위해 공동 주문 방을 만들고 참여하는 모바일 서비스다. 처음에는 핸드폰 번호 로그인, 방 생성, 메뉴 입력, 금액 합산, 모집 상태 관리까지 만든다. 이후에 WebSocket, OCR, 정산 자동화, AWS 배포를 붙여 실전 서비스에 가까운 구조로 키운다.
